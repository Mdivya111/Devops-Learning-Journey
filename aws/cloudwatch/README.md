AWS CloudWatch
1. What is Amazon CloudWatch?
Amazon CloudWatch is an AWS monitoring and observability service used to monitor AWS resources, applications, and infrastructure.
It collects and provides access to:
- Metrics
- Logs
- Alarms
- Dashboards
- Operational data
Simple understanding
Think of CloudWatch as a monitoring system for AWS.
It helps answer questions such as:
- Is my EC2 CPU usage too high?
- Are there application errors?
- Is a resource behaving normally?
- Should I receive an alert?
Technical definition
Amazon CloudWatch is an AWS monitoring and observability service that collects, monitors, analyzes, and acts on metrics, logs, and other operational data.

2. CloudWatch Metrics
A metric is a numerical measurement collected over time.
Examples for EC2:
- CPU utilization
- Network traffic
- Disk operations
- Network packets
Example:
CPUUtilization
10%
25%
60%
85%

CloudWatch can monitor these values and detect unusual or high usage.
Important
Metric ≠ Alarm
A metric is the data.
An alarm uses that data to determine whether a condition has been met.
3. CloudWatch Logs
CloudWatch Logs allows applications, servers, and AWS services to send log data to CloudWatch.
Logs can contain:
- Application errors
- System events
- Login attempts
- API requests
- Troubleshooting information
Example:
Application started
User logged in
Database connection failed
ERROR: Payment failed

For an EC2 instance, the CloudWatch Agent can be used to collect log files and send them to CloudWatch Logs.
4. Log Group
A Log Group is a container used to organize related log streams.
Example:
Log Group: /app/production

It can contain multiple log streams.
Think:
Log Group = folder containing related logs

5. Log Stream
A Log Stream is a sequence of log events from a particular source.
Example:
Log Group
   ├── EC2-instance-1
   ├── EC2-instance-2
   └── EC2-instance-3

Each stream can contain log events generated by that particular source.
6. Log Event
A log event is an individual log record.
Example:
2026-09-27 20:15:32
Database connection failed

So the hierarchy is:
CloudWatch Logs
      ↓
Log Group
      ↓
Log Stream
      ↓
Log Events

7. CloudWatch Agent
The CloudWatch Agent is software that can be installed on servers such as EC2 instances.
It can collect:
- Additional system-level metrics
- Memory utilization
- Disk utilization
- Log files
- Custom metrics
and send them to CloudWatch.
Important distinction
Some basic EC2 metrics are available automatically through AWS.
The CloudWatch Agent is useful when you need additional OS-level metrics or log collection.
8. CloudWatch Alarms
A CloudWatch Alarm monitors a metric and checks whether it meets a defined condition.
Example:
CPUUtilization > 80%

If the condition is met, the alarm can enter the ALARM state.
It can then trigger supported actions such as:
- Sending an SNS notification
- Triggering an Auto Scaling action
- Other supported AWS actions
Alarm states
- OK → metric is within the expected condition
- ALARM → threshold/condition has been breached
- INSUFFICIENT_DATA → CloudWatch doesn't have enough data to determine the state
Important
Alarm = action/alert based on a metric condition.

9. CloudWatch Dashboards
A CloudWatch Dashboard provides a visual view of monitoring information.
You can put multiple metrics and monitoring information into one dashboard.
Example:
Production Dashboard

EC2 CPU       → 65%
Network       → Normal
RDS CPU       → 45%
Lambda Errors → 2

Difference
Metric → actual monitoring data
Dashboard → visualizes monitoring data
10. CloudWatch Namespace
A namespace is a logical container used to group related metrics.
Examples:
AWS/EC2
AWS/RDS
AWS/Lambda

For example:
AWS/EC2
   ├── CPUUtilization
   ├── NetworkIn
   └── NetworkOut

Technical definition
A CloudWatch namespace is a logical container used to organize metrics by AWS service or metric source.

11. CloudWatch Dimensions
A dimension is a name-value pair that provides additional information about a metric and helps distinguish metrics for a particular resource or context.
Example:
Metric: CPUUtilization

Dimension:
InstanceId = i-123456

Another EC2 instance can have:
InstanceId = i-789012

Remember
Namespace → groups metrics
Metric → what is being measured
Dimension → identifies/distinguishes the resource or context
12. Metric Period
A metric period is the length of time over which CloudWatch aggregates metric data points.
Examples:
1 minute
5 minutes
10 minutes

If the period is 5 minutes, CloudWatch can aggregate the metric data for each 5-minute interval.
Remember
Period = How much time are we looking at?

13. CloudWatch Statistics
Statistics are aggregated values calculated from metric data points over a specified period.
Common statistics include:
- Average
- Sum
- Minimum
- Maximum
- Sample Count
Example:
Values:
20, 30, 40

Then:
Average     = 30
Sum         = 90
Minimum     = 20
Maximum     = 40
Sample Count = 3

Remember
Period → over what time?
Statistic → how do we summarize the data?
14. Metric Resolution
Metric resolution determines how frequently metric data points are recorded.
For example:
Every 1 minute → higher resolution
Every 5 minutes → lower resolution

Important distinction
Resolution → how frequently data points are recorded
Period → the time interval over which data points are aggregated
15. CloudWatch Logs Insights
CloudWatch Logs Insights is used to search, query, and analyze logs stored in CloudWatch Logs.
Instead of manually going through thousands of log messages, you can query the logs to find specific information.
For example:
Find all ERROR messages from the last hour.

Technical definition
CloudWatch Logs Insights is an interactive log-analysis capability that allows users to query and analyze log data stored in CloudWatch Logs.

Remember
CloudWatch Logs → stores/collects logs
Logs Insights → searches and analyzes those logs
16. EventBridge Relationship
Amazon EventBridge is an AWS event-driven service that receives and routes events to targets.
Simple example:
EC2 instance state changes
          ↓
     EventBridge
          ↓
      Target/action

CloudWatch vs EventBridge
CloudWatch → primarily monitoring and observability
EventBridge → primarily event-driven automation and event routing
They can work together in an AWS architecture, but they have different primary purposes.
17. CloudWatch vs CloudTrail
This is a very important interview difference.
CloudWatch	CloudTrail
Monitoring and observability	Auditing and governance
Metrics and logs	AWS API/account activity
Monitors resource/application behavior	Records who performed AWS actions
Example: EC2 CPU is 90%	Example: who terminated an EC2 instance


Easy way to remember
CloudWatch = What is happening?

CloudTrail = Who did what?

18. Common DevOps Use Case
Suppose an application running on EC2 becomes slow.
A DevOps engineer might investigate:
EC2
 ↓
CloudWatch Metrics
 ↓
Check CPU / Network / Disk
 ↓
CloudWatch Logs
 ↓
Find application errors
 ↓
CloudWatch Alarm
 ↓
Alert/automated action

CloudWatch therefore helps with monitoring, troubleshooting, alerting, and operational visibility.
CloudWatch — Interview Questions
1. What is Amazon CloudWatch?
Answer:
“Amazon CloudWatch is an AWS monitoring and observability service used to monitor AWS resources and applications through metrics, logs, alarms, dashboards, and other operational data.”

2. What is the difference between CloudWatch Metrics and CloudWatch Logs?
Answer:
“Metrics are numerical measurements collected over time, such as EC2 CPU utilization. Logs are records of events or messages, such as application errors or system events.”

3. What is a CloudWatch Alarm?
Answer:
“A CloudWatch Alarm monitors a metric against a defined condition or threshold and can trigger notifications or supported automated actions when that condition is met.”

4. What is a CloudWatch Namespace?
Answer:
“A CloudWatch namespace is a logical container used to group and organize metrics by AWS service or metric source. For example, EC2 metrics are generally under the AWS/EC2 namespace.”

5. What are CloudWatch Dimensions?
Answer:
“Dimensions are name-value pairs that provide additional information about a metric and help identify or distinguish the resource or context associated with that metric.”

6. What is the difference between a metric period and metric resolution?
Answer:
“Metric resolution refers to how frequently data points are recorded, while the metric period refers to the time interval over which those data points are aggregated.”

7. What are CloudWatch statistics?
Answer:
“Statistics are calculations used to summarize metric data over a specified period. Common statistics include Average, Sum, Minimum, Maximum, and Sample Count.”

8. What is CloudWatch Logs Insights?
Answer:
“CloudWatch Logs Insights is used to query, search, and analyze log data stored in CloudWatch Logs, which is useful for troubleshooting applications and systems.”

9. What is the difference between CloudWatch and CloudTrail?
Answer:
“CloudWatch is primarily used for monitoring and observability, while CloudTrail is primarily used for auditing AWS API and account activity. CloudWatch can tell us about resource behavior, while CloudTrail can show who performed an AWS action.”

10. An EC2 application is running slowly. How would you use CloudWatch to troubleshoot it?
Answer:
“I would first check relevant CloudWatch metrics such as CPU utilization, network activity, and disk-related metrics. Then I would check application and system logs in CloudWatch Logs for errors or unusual events. I would also review any configured CloudWatch alarms to identify threshold breaches or alerts.”
